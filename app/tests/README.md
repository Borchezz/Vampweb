# Проверки ночных добавок

## Автоматические проверки правил

Из корня проекта с установленным Node.js:

```bash
npm --prefix app test
```

Зависимости устанавливать не требуется: используется встроенный `node:test`.

Проверяются каталог, бесконечность барных и расход медицинских добавок, миграция старого профиля, уникальность четырёх ячеек, хранение по профилям, ограничение одной барной добавки в коктейле, signed-эффекты, временные пожелания, множители и удовлетворение. Отдельные интеграционные проверки запускают каждую из 30 новых добавок через реальный расчёт коктейля.

## Браузерные сценарии

`nighttime-additives.browser.js` экспортирует проверки для запуска в консоли браузера или через автоматизацию. **Только в изолированном тестовом браузере/профиле:** сценарии меняют localStorage этого браузера и настройки диапазона компонентов. Не запускать поверх личных черновиков.

На чистом тестовом origin открыть `?mode=nighttime`, дождаться загрузки и выполнить:

```js
const tests = await import('/tests/nighttime-additives.browser.js');
await tests.testBarAdditiveShelf();
tests.testAdditiveCategoryEditor();
await tests.testBarAdditivePreparation();
tests.testBarShelfEditorReachable();
```

Последний сценарий оставляет редактор открытым. Первый требует первоначально пустую барную полку; не выполнять второй раз без отдельного тестового origin либо осознанного сброса только тестовых ячеек.

Дополнительно проверить:

- после перезагрузки страницы выбранные барные добавки остались;
- при 0 случайных конечных компонентах барная полка всё равно доступна;
- после переключения профиля компонентов полки не смешиваются;
- при выключенном ограничении ресурсов медицинские компоненты работают как раньше;
- в `?mode=full` проходит `testBarAdditiveShelf()` на изначально пустой полке; ночная поверхность в этом режиме скрыта существующим дизайном;
- `?mode=daytime` загружается без ошибок;
- на узком экране нет горизонтального переполнения, кнопки очистки не перекрыты редактором.

Для смены выбранной добавки в игре: включить «Редактор», прокрутить до барной полки, нажать крестик на нужной ячейке и выбрать новую добавку. В standalone-ночном режиме панель редактора расположена слева, а на узком экране ограничена по высоте, чтобы не закрывать полку.

Барные ячейки хранятся отдельно от конечных запасов по ключу `bloodbar-nighttime-bar-additive-slots:<componentProfileId>`. Это browser storage, а не JSON-профиль дневного редактора и не сохранение Git.

## Расширенные эффекты

В отдельном чистом тестовом браузере после загрузки ночного режима:

```js
const effects = await import('/tests/nighttime-effects.browser.js');
await effects.testSuppressedTagPresentation();
await effects.testSingleBarLimit();
await effects.testLivePreferenceEffects();
await effects.testDrinkBoostExamples();
```

Сценарий случайных эффектов создаёт тестовых клиентов в browser storage. Он проверяет сохранение цели при перерисовке, перемешивании, удалении/повторном добавлении, переносе в другой слот и очистке коктейля. Новый визит позволяет новый выбор. Удаление ингредиента снимает эффект, но не забывает выбор. Также проверяются затенение групп крови и предотвращение гемолиза «Расщепителем». Отдельный сценарий проверяет четыре примера усиления напитка «Нектаром»/«Амброзией» и неизменность пожеланий клиента.

### Принятые правила

- В коктейле два общих слота добавок, но барная среди них может быть только одна. Медицинских может быть две.
- Окситоцин: −1 «Бодрящий» и +1 к итоговому удовлетворению.
- Степени не ограничены прежними максимумами 3/2. Случайная исходная генерация пожеланий по-прежнему использует свои диапазоны.
- Снижение случайного пожелания допускается для любого тега, включая теги без степени. Повышение — только для тегов со степенью. Нулевая степень и подавленные группы крови видимы затенёнными и не участвуют в оценке.
- Пожелания меняются только в копии для текущего коктейля, не в сохранённом профиле. Удаление добавки снимает её эффект. Случайный выбор принадлежит визиту клиента: удаление добавки, смена слота и очистка коктейля его не сбрасывают. Только начало нового визита очищает историю выбора.
- «Нектар» повышает один уже присутствующий активный желаемый тег напитка на +1. «Амброзия» распределяет два повышения по +1 между разными подходящими тегами; если подходящий тег один, обе единицы могут достаться ему. Усиление не создаёт отсутствующие теги, не оживляет подавленные и никогда не превышает желаемую степень. Пожелания клиента не повышаются. Случайный порядок желаемых тегов фиксируется на визит даже при первом применении без подходящих тегов напитка.
- «Медиатор» снижает по одному пожеланию ровно из «Хочет» и «Не хочет». Кортизол выбирает среди «Целебный»/«Потенциал» только положительные пожелания, отдавая приоритет «Очень хочет»; при равенстве выбор случайный и фиксированный. Если другая добавка подавила выбранное пожелание, Кортизол следует оставшемуся актуальному пожеланию, не перебрасывая случайные эффекты других добавок.
- EPO принудительно делает напиток густым, подавляя конфликтующую жидкую консистенцию. Пожелания к крови игнорируются, но группы крови самого напитка остаются, в отличие от «Расщепителя».

### Порядок расчёта

Сначала суммируются положительные теги всех компонентов, затем отрицательные. Отрицательная поправка сама по себе не создаёт отсутствующий тег. Затем добавляются состав/подача, подавляются пожелания к крови, применяются временные изменения пожеланий и принудительная густота. После этого — множители и выбор тега по пожеланию. После нейтрализации крови применяется усиление желаемых тегов напитка. Все условные эффекты смотрят на один последующий снимок напитка и временных пожеланий; положительное и отрицательное условия «Плацебо» могут взаимно компенсироваться. Поправки удовлетворения складываются отдельно.

### Обновление сохранённых каталогов

Формат массива сохранён; marker `<ключ компонентов>:version` повышен до `4`. Переход со старых версий добавляет отсутствующие новые ID, сохраняя пользовательские изменения. Переход с версии 3 меняет только точно совпадающие прежние встроенные эффекты «Нектара»/«Амброзии» на `preferred_tag_boost` с `units:1/2`; изменённые пользователем эффекты и описания сохраняются. Намеренные удаления и пустые каталоги версии 3 сохраняются. Миграция остаётся в памяти до сохранения. Четыре барные ячейки при обновлении не перезаполняются автоматически.
