# Локальный Git для Bloodbar

## Договорённости

- Репозиторий локальный. Удалённый сервер не подключён; отправка в интернет — только по отдельному решению Антона.
- Основная ветка — `main`. Начальная версия отмечена тегом `baseline-portable`.
- Первый коммит включает исходный проект, ресурсы и `Bloodbar.exe`, а также эти служебные файлы. EXE включён осознанно для сохранения исходной запускаемой версии.
- Перед обычным коммитом помощник объясняет изменения, показывает состав и результаты проверок, предлагает сообщение и ждёт разрешения. Запрос на конкретный коммит уже считается разрешением на него.
- Для существенного эксперимента помощник предлагает отдельную ветку, объясняет цель и согласует её создание/слияние. Маленькие согласованные изменения не требуют ветки автоматически.
- Чужие или незнакомые незакоммиченные изменения не стирать и не включать в коммит без выяснения.
- `reset --hard`, `clean`, удаление веток и отбрасывание файлов — только после объяснения потерь и явного подтверждения.
- Не нажимать игровую кнопку «Публикация» ради Git-коммита: серверная публикация — отдельный механизм.

## Термины

- **Репозиторий** — проект вместе с историей в скрытой папке `.git`.
- **Коммит** — именованная контрольная точка. Git фиксирует только добавленные в индекс файлы, не всё автоматически.
- **Рабочая папка** — файлы, которые сейчас редактируются.
- **Индекс / staging** — подготовленный набор изменений для следующего коммита.
- **Ветка** — отдельная линия разработки. Переключение ветки меняет файлы рабочей папки.
- **Тег** — неподвижное имя важной версии.
- **Diff** — различия между версиями.
- **Revert** — новый коммит, отменяющий выбранный старый коммит без стирания истории.
- **Remote** — адрес другого репозитория; здесь его пока нет. Git не равен GitHub и работает без интернета.

## Безопасные команды просмотра

В Git Bash сначала перейти в папку:

```bash
cd /d/Games/Vamp/Bloodbar
```

```bash
git status                    # Что изменено и что подготовлено
git diff                      # Изменения, ещё не добавленные в индекс
git diff --staged             # Что войдёт в следующий коммит
git log --oneline --decorate --graph --all  # История и ветки
git show baseline-portable --stat          # Состав исходной версии
git remote -v                 # Сейчас должно быть пусто
```

Для первого просмотра старой версии безопаснее попросить помощника сделать отдельную копию через `git worktree`, а не переключать текущую папку с незавершённой работой.

## Обычный рабочий цикл

1. `git status`: установить исходное состояние и не затронуть незнакомые изменения.
2. Согласовать одну понятную задачу; при необходимости создать ветку.
3. Внести правки и проверить затронутое поведение.
4. Посмотреть diff, добавить конкретные файлы в индекс, проверить staged diff.
5. После согласования сделать небольшой тематический коммит.
6. Проверить историю и состояние рабочей папки.

Не использовать слепое `git add .` для обычной работы: оно может захватить посторонние файлы. Исходная полная фиксация — отдельный случай.

## Что Git здесь НЕ сохраняет

- Браузерные черновики, настройки и данные в localStorage.
- Профили редактора из `%LOCALAPPDATA%\Bloodbar\editor-workspace` и других внешних рабочих каталогов.
- Несохранённые изменения текущей игровой сессии.
- Игнорируемые временные файлы и секреты.

JSON внутри `app/data/editor/` отслеживаются, но внешний workspace или браузерный черновик может перекрывать их при запуске. Откат Git сам по себе не откатывает эти внешние данные.

Git в той же папке — защита от неудачных правок, но не от поломки диска. Для резервного копирования нужна отдельная копия, включающая `.git`; её настройка не входит в текущую инициализацию.

## Технические решения

Настройки имени/email и отключение автоматической конвертации окончаний строк заданы только этому репозиторию. `.gitattributes` сохраняет точные байты исходных файлов; нормализация строк возможна позже отдельным согласованным коммитом. Глобальные настройки Git не менялись.
